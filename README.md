# Accord

イラストレーターとマネージャーの2人で使う、依頼・メディア・チャットの管理アプリ。
Discord・Notion・画像整理ソフトの3つを、このアプリ1つにまとめるのがバージョン1の目的。

- 設計書：https://claude.ai/code/artifact/9c8a734d-4b1a-4a61-bb37-19e9e8b274b7
- 試作：`docs/prototype/依頼ノート.html`（メディアの仕組みはここから移植する）

## 今の動かし方（ローカル版）

今はサーバーを使わず、データはブラウザの中（IndexedDB）に保存している。まず画面と操作を作り、あとでサーバー版（Supabase）に移す。

```bash
npm run dev
```

http://localhost:3000 を開く。初回は「マネージャー」（ID は `manager`）「イラストレーター」（ID は `illustrator`）の2人と、ルーム「依頼ノート」、チャット「雑談」が自動で作られる。

ログインの画面が出るので、新規登録するか、「試し用の利用者で入る」から2人のどちらかで入る（ローカル版だけ。パスワードなし）。ログインしたアカウントは、左下のカードの「アカウントを切り替え」で替えられる。どのアカウントで操作しているかはタブごとに覚えるので、2つのタブを別々の人にすればチャットのやり取りを試せる。

## ログイン（ローカル版と Supabase 版）

ログインまわりの画面（`/login`・`/signup`・`/forgot-password`・`/reset-password`）は1つで、`.env.local` の有無で動きが替わる。入口は `src/lib/auth/index.ts`。

- **ローカル版**（`.env.local` が無いとき）：アカウントはブラウザの中（IndexedDB の `accounts`）に保存する。パスワードは PBKDF2 でハッシュにしてから保存するが、本当の守りにはならない。メールは送らず、パスワードの再設定のリンクは画面に出す。Google でのログインは使えない
- **Supabase 版**（`.env.local` に URL とキーを入れたとき）：Supabase Auth を使う（メールとパスワード・Google）。メールのリンクと Google からは `/auth/callback` に戻る。`src/proxy.ts` がページを開くたびにログインの期限を延ばす。プロフィール・ルームとメンバー・フレンド・ルームへの招待・メディアのボックスと共有先（0003）は Supabase の表に保存し、`src/lib/local/sync.ts` がブラウザの中（IndexedDB）に写す（プロフィールとルームは「最後に変えた時刻」を先に読み、変わったものだけ中身を読む）。ルームの中のもの（カテゴリー・チャット・発言・既読・イメージユーザー・データベース・ページ・ビュー・予定・ToDo・ノート・ウィンドウ）と、ボックスの中のもの（画像の情報・ライブラリー）は、ブラウザの中に書いた行を `src/lib/local/rowSync.ts` が Dexie のフックで拾って Supabase の `synced_rows`（0011）に送り、ほかの人の行は Realtime と「前に読んだあとに変わった行」の読み直しで届く。届いた行は、中身が置き場所（ルームか DM）と合うかを確かめてから書く。画面は今までどおりブラウザの中を読む。DM の ID は2人で決まる（`dmChatId`）。ページの本文・「ページ」の項目の別ページ・チャットの項目のチャットも、ページから決まる ID で作る（2人がほぼ同時に初めて開いても1つにまとまる）。ホストのブラウザは、自分のルームの中身のうち Supabase にまだ無い行を1回だけ送る（すでにある行は上書きしない）。ノートはブロックごとにまとめて取り込む（NoteEditor）。共有をやめたとき・ボックスを消したときの画像の移し替えは Supabase の関数（remove_box_share・delete_box：0014）で行う。マイメディアは登録したときに Supabase で作られたものを使う。オンライン表示は、開いている間30秒おきに `presence_beat` で記録し、見せてよい人（フレンド・同じルームの人）の記録と選んだ状態を `presence_list` で30秒おきに読む（0015・0016。「オフライン表示」の人の記録は本人にしか返さない。時刻は何秒前かでやり取りする）。画像のファイルそのものは Cloudflare R2 に置く（第3段階：`src/lib/media/remote.ts`）。置く・読む札（署名付き URL）は `/api/media/sign` が、Supabase で見られる画像か・編集できるボックスかを確かめてから出す（R2 の鍵はサーバーの環境変数 `R2_ACCOUNT_ID`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`・`R2_BUCKET` だけに置く）。ブラウザは R2 に直接置き、ほかの人の画像は取ってきてブラウザの中に残す（一覧は小さい画像だけ、元の画像は拡大や編集のときだけ）。DM やノートに貼った画像は、それを見られる人なら見られる（`media_for_ids_checked`：0017）。完全に削除した画像（入れた本人が消したもの）と、編集する前の版のファイルは、`/api/media/delete` が Supabase で確かめてから R2 からも消す

Supabase につなぐとき：

1. Supabase でプロジェクトを作り、`.env.local.example` を `.env.local` にコピーして URL とキーを入れる
2. `supabase/migrations/` の SQL を順に SQL Editor で実行する
3. Authentication → URL Configuration：Site URL に `http://localhost:3000`、Redirect URLs に `http://localhost:3000/auth/callback` を足す（公開するときは、公開先の URL も）
4. Google でログインするときは、Authentication → Providers → Google を有効にし、Google Cloud で作った OAuth クライアントの ID とシークレットを入れる
5. `npm run dev` を起動し直す

### 公開するとき（本番ではローカル版を動かさない）

公開したもの（`npm run build`）は、Supabase の URL とキーが無いと、ローカル版で動かずに「まだ使える状態ではありません」の画面だけを出す（`src/lib/auth/mode.ts` の `localModeBlocked`）。ローカル版のままだと、試し用の2人が自動で作られて誰でもパスワードなしで入れ、データもその人のブラウザの中だけになるため。

- 公開先の環境変数に `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を入れてからビルドする（`NEXT_PUBLIC_` の付くものはビルドのときに埋め込まれるので、入れたあとはビルドし直す）
- 試しにローカル版のまま公開するときだけ、`NEXT_PUBLIC_ALLOW_LOCAL_MODE=1` を入れてビルドする
- 開発中（`npm run dev`）は、今までどおりローカル版で動く

ページが見つからないとき・思わぬエラーのときは、日本語の画面を出す（`src/app/not-found.tsx`・`error.tsx`・`global-error.tsx`）。アプリのアイコンは `src/app/icon.svg`（ブラウザのタブ）と `src/app/apple-icon.tsx`（iPhone のホーム画面）。

### ロボットよけ（Cloudflare Turnstile）

ログイン・新規登録・パスワードの再設定の画面に、Cloudflare Turnstile の確認の欄を出す（`src/components/auth/Turnstile.tsx`）。キーを入れないときは、開発中（`npm run dev`）は Cloudflare の試し用のキー（いつも通る）で動き、公開したもの（`npm run build`）では出ない。

- **ローカル版**：届いた token を、このアプリのサーバー（`/api/turnstile`）が Cloudflare に問い合わせて確かめてから、ログインなどに進む
- **Supabase 版**：token を Supabase に渡し、Supabase が確かめる。Supabase の設定でロボットよけをオンにすると、設定の画面でパスワードを確かめるとき（メールアドレス・パスワードの変更、アカウントの削除）にも確認の欄が出る

本物のキーにするとき：

1. Cloudflare のダッシュボード → Turnstile → サイトを追加（ドメインに `localhost` と、公開先のドメインを入れる）
2. 出てきたサイトキーを `.env.local` の `NEXT_PUBLIC_TURNSTILE_SITE_KEY` に入れる
3. シークレットキーは、ローカル版なら `.env.local` の `TURNSTILE_SECRET_KEY`、Supabase 版なら Supabase の Authentication → Attack Protection（Bot and Abuse Protection）で CAPTCHA をオンにして、Turnstile を選んで入れる
4. `npm run dev` を起動し直す

Supabase でロボットよけをオンにしたのに、`.env.local` に本物のサイトキーが無い（試し用のキーのまま）と、ログインが通らなくなるので気をつける。

アカウントの削除は、ホストになっているルームがあるとできない（ホストは引き継げないため。Supabase 版は `delete_my_account`（0008）で止める）。

### アカウントの ID とルームへの招待

- **ID**：Discord のユーザー名と同じく、ほかの人と重ならない名前（半角の英小文字・数字・「_」「.」で2〜32文字。決まりは `src/lib/username.ts`）。新規登録のときに自分で決め、アカウントの設定 → マイアカウントで変えられる。前からいた人と Google で登録した人には、名前から仮の ID を付ける（メールアドレスからは作らない）。名前の下に出し、横のボタンで写せる
- **フレンドの申請**は ID だけで送る（名前では探さない）。ローカル版だけ、「フレンドを追加」の下に登録されている人の ID を出す
- **ルームへの招待**：ルーム名のメニュー・ルームの設定の「フレンドを招待」か、フレンドの「…」→「ルームに招待」から送る。フレンドとの DM に招待のカードが届き、相手が「参加する」を押すとメンバーになる（期限7日。送った人がカードを消すと取り消し。`src/lib/local/invites.ts`）。招待できるのはホストと、ホストがルームの設定で「メンバーもフレンドを招待できる」をオンにしたときのメンバー
- Supabase 版の形は `supabase/migrations/0009`（ID・`send_friend_request`・`room_friend_invites` と参加の関数）

- データの出し入れは `src/lib/local/` にまとめてある。サーバー版に移るときは、ここを差し替える
- サーバー版のデータベース設計は `supabase/migrations/`、接続部品は `src/lib/supabase/`。Supabase 版で使っているのは、プロフィール・ルーム・フレンド・招待（0010）と、ルームの中のもの（0011〜0013）、メディア（0014）、オンライン表示（0015・0016）、貼られた画像（0017）まで
- 設定の「名称表示」をオンにすると、カーソルを置いた場所の名前が出る（改善の指示を出すとき用）。区画の名前は各部品の `data-name` 属性で付けている
- データを消して最初からやり直すときは、ブラウザの開発者ツール → Application → IndexedDB → `irai-note` を削除する

## 開発ステップ（設計書 9章）

1. 土台：ルーム、メンバー、サイドバー（ローカル版。ログインと招待リンクはサーバー版で） ✓
2. メディア：試作の仕組みを移植（ローカル版は画像をブラウザに保存） ✓。PSD（PSB も）も入れられる。PSD はブラウザが表示できないので、追加するときに統合した画像を PNG にして表示に使い、ダウンロードや ZIP では元の PSD を出す（`src/lib/media/psd.ts`。統合した画像の無いファイルはレイヤーを重ねて作るので、調整レイヤーやレイヤー効果は出ない）。上のバーの検索で、今いる場所の中（ホームではボックス全体）の画像を、名前・ファイル名・形式・追加した人で絞り込める（全角と半角、カタカナとひらがなの違いは気にしない。空白で区切ると、すべてを含むもの）
3. チャット：リアルタイム、メディア経由の画像送信、未読数（ローカル版。スマホへの通知はサーバー版で） ✓。既読は LINE と同じく自分の発言の左に「既読」（読める人が2人以上なら「既読 2」。押すと読んだ人・まだの人）。チャットが画面に見えているときだけ既読にする。通知はブラウザの通知で、アプリを開いている間に、開いていないチャットへほかの人の発言が届いたら出す（アカウントの設定の「通知」で端末ごとにオン、チャットごとにはチャットの上のベルで切れる。取り込み中は出さない。`src/lib/local/chatNotify.ts`）。通知はサービスワーカー（public/media-sw.js）から出すので、Android の Chrome でも出る。閉じているときの通知（Web Push）と iPhone はサーバー版で
4. 依頼：依頼データベース、ビュー（現在の依頼・テーブル・タイムライン・カレンダー・収入・終了した依頼）、依頼進行チャットとやり取り再現チャット、Notion からの取り込み ✓
5. ノート：ブロック式のノートページ（画像はメディアから、依頼ビューの埋め込み、依頼ページのメモ） ✓。左右に並べたブロック（列）は、スマホの幅（768px 未満）ではタブになり、1列ずつ横いっぱいに見せる（ノート・ウィンドウ・ページの本文で共通。保存する中身は変えないので、パソコンでは左右に並んだまま。`src/components/note/columnTabs.tsx`）
6. DM：ルームバーいちばん上のボタンから開く。フレンド（ID で申請・承認・解除）とフレンドとのDM（ローカル版）。ルームへの招待は DM にカードで届く。DMで送った画像は送った人のマイメディアに入る（ほかのボックスから選んだ画像はコピー）。受け取った人は「マイメディアに保存」で自分のマイメディアに残せる
7. メディアボックス：メディアをルームから切り離し、持ち主のいるボックスに入れた。一人ひとりに削除できない「マイメディア」があり、ボックスは何個でも作れる。ルームのメディアは、ルームに紐づいたボックス（ルームを作ると一緒にできる）。DMの「メディア」でボックスの一覧と中身を開ける
8. ボックスの共有：持ち主がボックスごとに、フレンドとの共有・ルームとの紐づけを「見るだけ／編集もできる」で決める（1つのルームに紐づけられるボックスは1つ）。見るだけなら、メディアの画面はコピーとダウンロードだけ。共有をやめる・フレンドを解除する・ルームを消すと、使えなくなった人が入れた画像はその人のマイメディアに移る。ボックスが紐づいていないルームの「メディア」には、チャット（データベースのページの中のチャットも含む）で送られた画像と「ボックスを紐づける」が出る（チャットを消すと一覧からも消える）。ルームを作るときに、メディアを「新しいボックス／自分のボックス／設定しない」から選ぶ。ルームのメディアを変えられるのは、ルームを作ったホストだけ。ホストは引き継げない（ホストは自分のボックスしか紐づけられないので、ルームに紐づくボックスの持ち主はいつもホストになる。サーバー版では supabase/migrations/0004 で止める）
